# 表格布局、性能与组件复查

日期：2026-10-19。基线为 `v0.17.0`，本轮修改通过 Changeset 登记为后续补丁，不将源码合入描述为已发布新 npm 版本。

## 展开列间距的原因与默认行为

原样式给非末列统一加 `min-width: 80px !important`；普通列映射又为辅助列填入业务默认宽度，展开/选择增强器随后丢弃显式元数据。宽屏自动布局还会把空余空间分给所有定宽列，不能只改一个 CSS 数字。

本轮将辅助列默认宽度收敛为选择 40、展开 40、序号 50。未声明宽度的普通非固定业务列保持自然弹性，并保留首选最小宽度；辅助列与弹性业务列共存时默认采用原生 fixed 布局。显式宽度、上限、固定位置、全局列宽和原生 table-layout 不被改写。所有业务列均显式定宽时保留原生余量分配语义。

相同 1440px 独立浏览器场景中，0.17.0 的三个辅助列各约 142.56px；修改后为 40/40/50px。该场景含一列未指定宽度、最小宽度 220px 的名称列，同时测试普通与固定列布局。详细配置见[表格指南](./guides/table-density.md)。

## 性能改进的可验证范围

| 位置           | 原问题                                        | 修改与验证                                                                          |
| -------------- | --------------------------------------------- | ----------------------------------------------------------------------------------- |
| 程序化跨页选择 | 每选择一个键都扫描本地数据                    | 首次使用时建索引，重复查询复用；1 万行选择末尾 100 行，rowKey 调用 995,150 → 10,100 |
| 批量展开       | 每个新键线性找行，差集反复 includes           | 惰性行键索引与 Set 差集；1 万键展开线性访问，不重复扫描                             |
| 树行辅助遍历   | 深度递归可栈溢出                              | 迭代 DFS，保留对象身份、顺序和循环/共享节点去重                                     |
| 表单修改检测   | 只判断是否修改仍比较所有字段                  | 首个差异短路；嵌套 Map/Set 修改仍可触发外层计算                                     |
| 图和甘特实例   | 第三方大型对象被 Vue 深代理，同帧配置多次重建 | 原始实例浅引用，甘特主题/配置合并监听与重复初始化取消                               |

以上是算法调用量和生命周期验证，不表示整表 FPS 按同比例提升。2 万深、15 万宽的辅助遍历测试不代表 Naive 原生能渲染同等规模的 DOM；实际大表仍应使用分页、虚拟滚动、稳定且唯一的 rowKey。

## 审查范围与后续空间

本轮逐项源码审读 51 个公开组件：表单/表格/树与分割、导航/标签/主题、消息/工作流、图表、媒体/编辑器、选择/拖拽、加载与其他工具组件。Map、OrgChart、FilePreview、Upload 在另一个活动工作区单独改进，本轮不覆盖或混入其未提交修改。公共 `_shared` 目录不计作业务组件。

审读重点是高频计算、重复初始化、事件/observer/计时器释放、异步任务身份、公开事件和 vendor 真实接入。只有已修改路径及明确场景有新增针对性回归，不能将源码审读等同于所有组件、浏览器、第三方引擎都做了压测。

仍有专项空间：WaterFall 图片布局批处理与窗口化、Chat/Transfer/GlobalSearch 等海量列表的窗口化、长字幕的时间索引、媒体运行时配置切换与大文档编辑性能。现有普通 DOM 列表并非无限数据容器；应按实际数据量和耗时/内存证据推进，不为了统一形式给所有组件加入自建虚拟滚动和更多开关。

次要异步状态仍可进一步完善：Code 快速切换语言时 loading 尚无独立请求代次；QRCode 的旧 Logo 图像请求虽不会提交过期结果，底层网络加载本身没有主动取消。这些没有作为本轮已修复项。

## 本轮实际校验

- 完整 `bun run verify` 通过：282 项单元、173 项真实组件挂载，以及 TypeScript、Vue/组件/消费者声明、lint、构建、ESM/CJS 与 Node16/NodeNext 打包消费者契约检查。
- 包与四个轻量入口的体积预算通过，未放宽预算；消费者契约复用本机安装的依赖版本，没有宣称重新从公开 registry 安装了尚未发布的补丁。
- 隔离浏览器以 1440/720/420px、明暗主题和三种密度组合运行 18 组场景、36 个表格实例，核对实际辅助列宽、表头/表体对齐、业务最小宽度、展开/收起、真实选择和页面错误。对比基线使用已发布 0.17.0 的实际产物。
- 本轮没有运行真实业务后端、没有给所有第三方引擎做性能压测，也没有以 Chromium 结果替代其他浏览器/平台验收。
