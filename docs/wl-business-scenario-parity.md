# WL 业务场景组合对照

本轮以现有 WL PC 页面的真实交互和数据字段为依据，建立三个可运行的离线对照场景。
范围是下表列明的交互契约；没有迁移 WL 项目、连接业务后端，也不把精简后的场景代码量与整个原页面直接比较。

## 来源与边界

| 场景                   | 源码依据                                                                                                                                                                                                      | 对照保留的行为                                                                                                                     | 仍由业务持有                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 生产主从多表           | `wl/produce/wl-ui-produce/src/views/produce/mps/rolling-plan/plan-scheduling/index.vue:127`、`data.ts:790`                                                                                                    | 订单池行驱动已选炉次与候选坯料两个独立区域；切换主行清空旧数据；同单号不同项次按行 ID 隔离；单区失败可独立重试                     | 库存、支数上下限、绑定／解绑、工单下发、权限、调度重算及保存事务 |
| 质量动态矩阵           | `wl/wl-ui-quality/src/views/quality/lims/steelmaking/lims-steelmaking-composition-result-confirm/index.vue:58`、`index.vue:174`、`data.ts:32`                                                                 | 三种设备、11 个动态元素列；按样品保留输入草稿；增删行至少留一行；空白不提交，字符串 `0` 与原始小数精度保留；载荷快照与后续编辑隔离 | 判据、量纲、数值合法性、删旧后保存事务、仪器采集与后端整合结果   |
| 分类物料／组织人员选择 | `wl/wl-ui-sale/src/views/sale/base/components/MaterialTreeListPicker.vue:19`、`:162`；`wl/produce/wl-ui-produce/src/views/produce/steelmaking/performance/batching/components/person-name-picker/index.vue:3` | 分类／组织筛选、三字段物料搜索、分页、值反查、取消不提交、确认才发布；同名人员按工号区分                                           | 实体权限、租户隔离、组织后代范围、人员或物料有效性及真实接口注册 |

生产场景额外用延迟响应回归验证：快速切换订单时，忽略取消信号的旧接口仍不能覆盖当前子表。
两个子资源共享订单键，分别拥有自己的请求、错误与重试状态。

质量设备列继续来自 `deviceNo / elements` 配置，行身份由本页生成。`edit: 'inline'` 常显输入直接更新受控草稿，匹配原页面连续录入的方式；切换样品时更换整个表格所属范围，旧控件不能继续更新另一个样品。
整合快照保留 `parentId / heatNo / heatId / smpNo / deviceNo / elementCode / testRst`；额外的 `id` 仅供离线结果表识别行，不是后端保存字段。

查询栏重置只重置该栏的搜索字段，分类通过“全部分类”清除。这与旧物料组件一次清空所有条件的交互有所区分，采用各区域分别持有自身条件的方式；搜索与重置均不暗中取消分类。

## 使用侧如何保持扁平

- 主从资源直接复用公开 `@robot-admin/naive-ui-components/workflows` 的 `useDataResource`，不在页面重复维护请求序号、取消控制器或加载状态。
- 表格继续使用 `C_Table` 的列配置、行键、编辑和 `update:data`，配合两个 `C_SplitPane` 组成真实有高度的上下／左右布局。
- 分类物料使用 `C_DataPicker`，组织人员使用 `C_UserPicker`；没有另建选择器外壳，也没有让人员组件处理物料业务。
- 分类和表单查询共用 DataPicker 的会话。自定义查询提交省略分类字段时，内核继承当前分类；显式提交该字段可以覆盖或清除；`fixedFilters` 保持最高优先级。
- 搜索表单从 query slot 的 `initialValues` 创建本次会话草稿，取消重开后与列表一起回到初始条件。没有第二份外部搜索状态或手工同步 watcher。
- 已确认的接口协议只在数据源中转换一次：`page/pageSize` → `current/size`，`data.records/total` → `rows/total`。组件不探测未知响应结构。

业务模型、设备配置和草稿缓存继续保留在场景 `data.ts`；这些代码没有进入组件包公共 API。

## 离线运行与检查

```bash
bun run build
bun run dev:search-workflows
# 打开 http://127.0.0.1:4188/business-scenarios.html

bunx --no-install vitest run --config vitest.config.ts tests/components/business-scenario-parity.component.ts
bun run type-check:components
bun run check:search-workflows
```

手工操作顺序：

1. 点击生产订单的两个项次，确认上下三表和两个分割手柄可用；点击“下次炉次查询失败”后切换项次，确认候选区仍有数据，“重试炉次”能单独恢复；清空订单后两个子表清空。
2. 在质量设备表中连续输入 `0`、`0.01000`，不需要逐格保存；切换样品再返回，确认草稿保留；增删设备行，确认不能删掉最后一行；生成整合载荷后继续输入，确认整合快照不会跟着改变。
3. 打开物料弹窗，选择“合金”、搜索编码、切页并取消，确认业务值未更新；重新打开，确认查询框与列表同步恢复初始条件；再次选择并确定后更新物料 ID。
4. 打开人员弹窗，分别选择两个班组中的同名人员，确认提交工号不同，组织筛选本身不会直接选中整组人员。

自动回归覆盖请求乱序、单区失败恢复、样品缓存及精度、真实表格编辑、接口字段映射、分类与查询组合、取消重开，以及组织筛选和业务身份。
测试结果只支持这些明确契约，不代表原页面的全部业务功能、WL 平台运行时或生产负载已经验收。
