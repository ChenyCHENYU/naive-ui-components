## 优化后复扫结论

- **常用组件接入保持扁平。** 本轮不要求使用侧补取消序号、重复选项状态或语言转换，底层修复即生效；不把领域协议推断或额外 DSL 引入组件。
- **C_Table 继续承担一般业务表格。** 现有列配置、编辑、虚拟列表与 C_SplitPane 足以支撑已建立的主从多表和质量矩阵对照契约；高级表格继续使用独立 MachTable 专项，不把两者揉在一起。
- **选择能力共用已有内核。** 分类物料由 C_DataPicker、组织选人由 C_UserPicker 复用树与选择会话，保持来源注册、分页、解析、草稿和确认的既有分层，未再增加一套查询缓存或选择状态机。
- **质量门禁覆盖真实产物。** 单测与挂载回归验证可控乱序、同步重入及生命周期；浏览器验证真实布局和交互；独立安装验证包声明和最低/最新依赖。各层证据各自成立，不互相代替。
- **剩余工作以业务数据驱动。** WL 三个场景仍是列明交互契约的离线同功能对照，不是 WL 所有页面迁移验收。真实权限、库存判据、仪器采集、保存事务、审批执行、多业务 UAT、读屏和长时堆内存需要对应环境验证；不因尚未接后端而增加模拟业务引擎。

目前未发现需要继续扩张公开 API 或整体重构的确定问题。后续优先用真实来源、典型数据规模与可复现故障验证，再针对实际瓶颈修复，保持现有架构和使用侧简洁。
