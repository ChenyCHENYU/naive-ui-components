# 依赖审计记录 · 2026-10-18

本轮常用组件收敛没有升级运行依赖。冻结锁文件安装完成后，`bun run check:audit` 仍以状态 1 退出，报告此前已记录的两项告警：

| 依赖               | 级别     | 已核实的路径与公告                                                                                                                                    |
| ------------------ | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `braces@3.0.3`     | high     | lint-staged、Changesets、Sass 等开发工具的 micromatch 依赖；[深嵌套模式导致栈耗尽](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)                 |
| `sprintf-js@1.0.3` | moderate | mammoth 的 argparse 1.x，以及 Changesets 的 js-yaml 3.x / argparse 1.x；[无界精度参数导致拒绝服务](https://github.com/advisories/GHSA-hp3w-g68c-fv3c) |

核查时官方尚未发布修复这两项公告的版本。直接升级 mammoth 也不能消除它的 argparse 1.x 依赖；未采用跨主版本强制 override、伪造版本或删除审计门禁。

常用组件首屏消费构建没有包含 mammoth；检查当前 mammoth 文档转换入口，也未发现它加载 CLI 使用的 argparse。这些结果有助于界定使用路径，但不能证明整个依赖树不存在风险，更不代表审计通过。处理不可信文档、命令行输入和构建模式时，仍需遵守宿主应用的资源限制及安全边界。

`check:audit` 与功能性的 `verify` 是独立检查。仓库 CI 继续在 `verify` 前执行审计；现有告警会使审计步骤失败，本文不将远端 CI 标记为通过。待上游发布兼容修复版后，应更新锁文件并重新运行审计、功能验证和发布消费者检查。
