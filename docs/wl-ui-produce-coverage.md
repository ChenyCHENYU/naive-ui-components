# wl-ui-produce 场景覆盖调研

调研日期：2026-10-18 至 2026-10-19。参考项目快照：`034832469bc8a45765988f67f9f2ce75e03cf005`。
这是源代码和场景能力核对，没有在参考项目替换组件、改动业务流程、调用后端写接口或完成迁移验收。

## 结论

本库可组合出常规管理端查询、录入、表格、主从分屏和树工作台。**不能宣称完整覆盖任何场景，也不能把 Naive UI 组件直接等同于 Element Plus + 平台 BaseTable / AG Grid。**
建议先在独立试验页面验证最常见的“查询 + 工具栏 + 主从表 + 录入弹窗”，保留应用领域逻辑。Element Plus 适配仍采用独立包，保持本库零 Element Plus / common-core 运行依赖。

## 分割手柄是否是一回事

两者都通过拖动分隔线调整相邻面板，可以嵌套。差别在于旧调用习惯：平台用 `top-height` / `left-width` 像素初值，本库 `size` / `defaultSize` 表达去除手柄后的第一面板百分比；百分比不能机械当成像素。

本轮补齐 `v-model:size`、`minFirstSize` / `minSecondSize` 像素下限、响应式边界、ResizeObserver、取消/失焦/卸载清理、键盘操作和折叠状态插槽。折叠时允许合法零尺寸；窗口小于两侧最小尺寸之和时按比例降级，避免负尺寸或溢出。持久化由页面按用户与页面隔离。

`c_steelListPanel` 自己监听尺寸并调用表格布局方法，说明表格响应尺寸不应耦合进 Split。Naive `flex-height` 表格仍需父层提供明确可计算的高度，并在 flex 中间层设置 `min-height: 0`；Tab、模态框和隐藏面板要分别验证初始化与重新显示。

详见[分割面板用法](./guides/split-pane.md)，Robot_Admin 的分割演示提供嵌套多表验证入口。

## 推荐收敛方式

1. 组件库维护通用交互与声明协议；查询/表单/表格共用密度，不复制三套尺寸常量。
2. 应用层提供小型字段与列适配函数，把公司、字典、数字精度和UI状态转换到目标组件；不把炼钢字段写进库。
3. 每张表拥有独立行键、查询控制器、选择与持久化key。主表变更时，页面负责清空从表、取消旧请求和重置从表分页。
4. 先验证数据密集、多表、Tab隐藏重显、窄窗口、暗色和错误重试，再评估迁移成本。需要AG Grid高级能力的页面保留原表格引擎。
5. Element Plus 适配包单独建设与测试，共享纯协议与算法，避免一个运行包同时拉入两套组件库。
